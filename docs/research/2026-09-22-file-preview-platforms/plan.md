# WebTerm 文件预览平台选型计划

## 决策问题

判断 `xushanpei/open-file-viewer` 是否适合作为 WebTerm 远程 SFTP 文件工作区的升级基础，并在格式覆盖、性能、稳定性、社区及运维成本之间选择更合适的方案。

## 假设

1. `open-file-viewer` 更可能是预览器而非可替换现有远程文件管理器、编辑器和会话持久化的核心。
2. 单一浏览器库不能同时给出高保真 Office 预览、低运维成本和广泛格式覆盖。
3. 分层预览（浏览器原生/专用组件优先，隔离式转换服务兜底）比整体引入一个文件管理产品更适配 WebTerm。

## 评估范围与标准

- 候选：open-file-viewer、PDF.js、docx-preview、SheetJS、kkFileView、ONLYOFFICE Document Server、Collabora Online。
- 指标：许可证、仓库活跃度与社区、格式能力、客户端性能、服务端资源与隔离风险、与现有 React + Go + SFTP WebSocket 架构的适配性。
- 来源：优先项目官方仓库、官方文档与许可证；社区信息只用于交叉验证。

## 风险与反证

- GitHub star 不等于安全性、维护承诺或可嵌入性。
- 声称支持的格式须区分浏览器端直读、转换后预览与可编辑。
- Office 服务端转换会处理不可信远程文件，必须单独隔离、限资源、无默认写回。

## 停止条件

为每个关键结论保存一手来源；对许可证、架构和格式范围存在不确定处明确标注，不以星数替代验证。
